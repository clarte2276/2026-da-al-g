# KIISE 프로그램위원회 심사 의견 — Reviewer C (1라운드)

## 1. 요약

본 논문은 철도 현장 안내 슬라이드와 규정 조항 사이의 승인된 링크 36건(96개 링크–조항 목표)을 대상으로, 같은 하이브리드 검색 후보에서 Jev, GPT 계열 LLM, 그리고 두 모델의 cascade 판정기를 비교한다. K=10에서 Jev choice는 LLM pair보다 정밀도와 반복 간 결정 일치율이 높고 비용·호출 지연이 낮지만, 재현율은 낮다. K=50에서는 Jev choice의 조건부 정밀도와 보정 오차가 좋아 보이는 반면, 승인 gold의 후보 포괄률은 49/96에 그친다. 저자들은 불완전한 gold, 단일 도메인, 대규모 비교의 미완료를 한계로 인정한다.

초안에 기재된 K=10 지표·비용·지연, K=50 후보 포괄률과 조건부 지표, downstream retrieval 평균은 `paper_jev/experiments/summary/main_table.md`, `edge_metrics.json`, `followup_summary.json`, `downstream_summary.json`의 값과 일치한다. 수치 자체의 불일치는 찾지 못했다. 다만 비용의 범위와 프롬프트·모델 설정, downstream 변형의 생성 절차가 논문에 충분히 드러나지 않아 핵심 효율성 주장을 독립적으로 재현하기 어렵다.

## 2. 점수

- 독창성: **3/5** — 도메인별 승인 링크 구성에서 구조화 판정 모델과 LLM의 정밀도·재현율·비용·보정을 같은 후보로 비교한 적용 기여는 유용하다. 다만 새 링크 생성 또는 검색 알고리즘을 제안하지 않고, 기존 choice·pair·cascade 구성의 비교에 머문다.
- 기술적 타당성: **3/5** — 동일 후보와 명시된 임계값으로 판정기를 비교하고 불완전 gold의 영향을 인정한다. 그러나 승인 링크만 양성인 자료라 미승인 예측을 실제 오류로 해석할 수 없으며, K=10 후보 포괄률도 26/96에 불과하다.
- 실험 설계·근거: **2/5** — 3회 반복은 동일한 링크·후보 표본에서 수행되고, K=100 Jev 지표는 1회만 완료됐다. downstream은 37건에 대해 변형별 `r1` 실행만 있어, 반복 API 호출 간 변동을 데이터·도메인 일반화의 근거로 삼을 수 없다.
- 관련 연구 위치짓기: **3/5** — RAG, KG²RAG, 법률 문서 상호참조, 확률 보정, cascade를 연결한다. 기존 연구를 검색과 링크 구성으로 구분한 점은 적절하지만 직접 비교 문헌과의 실험적 차이는 제한적이다.
- 명확성·작성: **3/5** — 구성과 한계는 간결하고 수치 출처도 대체로 추적 가능하다. `결정 일치율`이 정확도와 혼동될 수 있고, 비용 집계와 downstream 실행 조건은 결과를 해석하기에 부족하다.
- 양식 준수: **4/5** — DOCX 구조는 A4, 지정 여백, 제목·요약 1단, 본문·참고문헌 2단이며 작성자 메타데이터가 비어 있다. 다만 DOCX의 페이지 수 속성은 양식 파일의 값과 같아 실제 산출 페이지 수를 입증하지 못하므로 제출 PDF에서 2~3쪽인지 확인해야 한다.
- 재현성: **2/5** — 후보 가중치, 반복 수, 임계값은 제시되지만 프롬프트 버전·API 모델 식별자와 날짜·호출 설정·샘플 seed·불변 코드 및 데이터 식별자가 논문에 없다. 일부 설정은 실험 저장소에만 있다.

**종합 점수: 2/5**

**판정: Weak Reject** — 관측 결과는 좁은 조건의 파일럿으로는 유의미하지만, 비용·재현성·downstream 평가를 검증할 실행 정보를 논문에서 확인하기 어렵고 반복 횟수도 일반화 근거가 되지 못한다. 아래 항목을 보완한 뒤 재심하는 것이 적절하다.

## 3. Must-fix (위치/문제/수정 요구)

1. **위치: §3.2 표 2 및 K=50 비용 설명 — 비용·지연 집계의 검증 가능성.**

   **문제:** 표는 USD와 누적 호출 초만 보여 API 호출 수, 입력·출력 토큰, 가격 단가를 제공하지 않는다. 비용은 3회 합계이고 지연은 순차 호출 시간 합계라 행 간 효율 비교를 검산하기 어렵다. 특히 K=50 cascade의 USD 1.601804는 낮은 K의 재사용 Jev 호출을 포함한 누적 비용이며, 집계 파일은 증분 비용 USD 1.209444도 별도로 기록한다. 두 값을 구분하지 않으면 단일 K 실행 비용으로 오해할 수 있다(`paper_jev/experiments/summary/main_table.md`, `paper_jev/experiments/summary/cost_latency.json`, `paper_jev/experiments/summary/followup_summary.json`).

   **수정 요구:** 표나 보충자료에 변형별 호출 수, 입력·캐시 입력·출력 토큰, 1회당 또는 사례당 비용, API 가격 출처와 조회 시점을 제시하라. Cascade는 Jev와 LLM 단계 비용을 나누고, K=50의 증분 비용과 재사용 호출을 포함한 누적 비용을 함께 표기하라. 총 지연이 로컬 처리 및 downstream 호출을 포함하지 않는다는 현재 범위 설명은 유지하라.

2. **위치: §2 방법 및 §3 실험 — 판정 요청의 재현 설정.**

   **문제:** 본문은 `gpt-5.6-luna`, Jev, 3회 반복을 언급하지만 API에 전달한 정확한 모델 식별자(`jev-latest` 포함), 날짜, 온도 및 출력 형식, 프롬프트, 반복 실행이 무엇을 바꾸는지 밝히지 않는다. 부정 슬라이드 80건은 77개에서 복원추출했지만 seed도 본문에 없다. 모델 alias와 공급자 응답은 바뀔 수 있으므로 결과의 시점과 요청을 고정할 수 없다. 실제 seed와 temperature 설정, 프롬프트는 `paper_jev/experiments/run_experiment.py`, `paper_jev/experiments/prompts/`, `paper_jev/experiments/README.md`에 있다.

   **수정 요구:** 지면이 부족하면 공개 보충자료에 정확한 요청 프롬프트 또는 파일 hash, 모델/API 식별자와 실행일, decoding·응답 설정, seed, 의존성 잠금 정보, 데이터·링크 snapshot과 코드 commit을 기록하고 본문에서 그 불변 식별자를 참조하라. 반복 간 표준편차가 모델 호출 변동을 뜻하는지 명확히 하라.

3. **위치: §3.3 후속 검색 및 표 — 변형 생성과 단일 실행 표시.**

   **문제:** 37개 질의의 Recall/MRR/nDCG@10은 각 링크 변형을 한 번(`r1`) 실행한 결과다. 실험 산출물에는 `gpt-5.6-luna`와 `text-embedding-3-small`이 기록돼 있고(`paper_jev/experiments/runs/downstream/*/ragas_results.json`), 링크 DB는 세 판정 반복의 다수결과 p≥0.5를 사용한다(`paper_jev/experiments/run_experiment.py`). 이 생성 절차와 단일 실행 여부가 본문 표에 없어, 표의 값만으로는 링크 설정 및 downstream 변동을 재현할 수 없다.

   **수정 요구:** 표 주석에 링크 집합의 threshold·다수결 방식, downstream LLM·embedding 모델, 실행 횟수(r1 단일 실행), 지표 계산 단위와 `via_link`가 정의된 표본 수(20/37)를 적어라. 단일 실행 결과는 평균적 성능 차이나 답변 품질 향상의 증거로 확대 해석하지 말라.

4. **위치: 초록, §3.2, §4 — 반복 변동과 일반화의 구분.**

   **문제:** 같은 96개 승인 목표와 같은 후보 집합에서의 3회 호출은 실행 간 변동만 보여준다. 독립 링크 표본이나 도메인 수준의 불확실성을 측정하지 않으며, 96개 목표도 36개 승인 기록에 종속돼 있다. K=10에서 후보 생성이 26/96만 포괄하고 K=100도 69/96이므로 판정기 지표는 전체 링크 복원의 상한과 분리해 해석해야 한다(`paper_jev/experiments/summary/main_table.md`, `paper_jev/experiments/summary/notes.md`).

   **수정 요구:** 평균±표준편차가 반복 호출 간 산포이며 신뢰구간이나 유의성 검정이 아님을 명시하라. 결론은 현재 승인 그래프와 후보 생성 설정에 대한 기술적 파일럿으로 한정하고, 더 넓은 도메인 일반화나 우월성으로 읽힐 표현을 피하라.

## 4. Should-fix

- **§3.2 표 2:** 초록의 `결정 일치율`을 `반복 간 동일 판정 비율`처럼 정확히 풀어 써 정확도와 혼동되지 않게 하라. K=50의 ECE 0.004는 후보로 포괄된 gold만을 대상으로 한 조건부 값임을 같은 표나 문장에서 분명히 하라.
- **§3.1–3.2:** 승인되지 않은 링크는 오답으로 검증된 것이 아니므로 precision·false positive를 현 승인 그래프와의 일치 지표로 계속 한정하라. K=10의 낮은 후보 포괄률과 K=100의 미완료 반복도 초록의 비교 결과 옆에서 유지하라.
- **§4 결론:** K=10 cascade의 평균 F1이 LLM pair보다 높다는 관찰은 반복 간 산포와 단일 도메인에 한정된 기술적 비교임을 바로 덧붙여 통계적 우위로 읽히지 않게 하라.
- 최종 제출본에서는 DOCX가 아니라 KIISE 제출용 PDF를 렌더링해 표·참고문헌이 잘리지 않는지, 실제 쪽수가 2~3쪽인지 확인하라. 양식의 작성자 비공개 지침은 현재 메타데이터와 본문에서 지켜지고 있다.

## 5. 사소한 점

- 참고문헌 [6]의 TypeSafe 블로그 항목은 URL과 게시/접근 날짜가 없다. `paper_jev/references/references.md`의 해당 항목에 있는 공식 URL을 포함해 서지 정보를 완성하라.
- 표 2의 `결정 일치율`, `누적 지연`, `비용`처럼 정의가 필요한 열 이름은 표 주석에서 반복 수와 집계 범위를 바로 확인할 수 있게 하라.
- K=50 단락의 `후보가 덮은 49/96 엣지에서 ... ECE=0.004`는 ECE와 precision이 후보 포괄 집합에 조건부라는 점을 문장 순서로 더 명료하게 쓸 수 있다.
