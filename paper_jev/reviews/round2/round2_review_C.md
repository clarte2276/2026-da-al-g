# KIISE 프로그램위원회 심사 의견 — Reviewer C (2라운드)

## 1. 요약

본 논문은 동일한 하이브리드 후보 생성기에서 Jev pair/choice, GPT-5.6 Luna pair/list, Jev–LLM cascade를 비교한다. 1라운드의 주요 지적에 대응해 K=10/50 후보 포괄률, 승인 링크 기록 단위의 종단 간 지표, 반복 간 표준편차와 군집 부트스트랩 구간, 호출 수·토큰·가격·지연, downstream의 단일 실행 조건을 훨씬 투명하게 제시했다. 초안의 수치는 paper_jev/experiments/summary/main_table.md, paper_jev/experiments/summary/round2/round2_tables.md, 비용·후속 실행 요약과 대체로 일치한다.

다만 초록의 “평균 비용”과 비용·시간 숫자는 표 2의 3회 합계여서 단위가 모호하다. 프롬프트 hash와 실행 설정은 저장소 내 재분석 표에서 확인되지만, 재현에 필요한 실험 코드 revision과 원본 DB/링크 snapshot 식별자는 없다. DOCX는 A4, 제목 1단·본문 2단이고 작성자 메타데이터가 비어 있으나, 저장된 2쪽 속성은 양식에서 물려받은 값으로 보이며 실제 페이지 수를 확인하는 PDF 렌더는 제공되지 않았다. 따라서 현재 자료는 승인 그래프와 한 철도 도메인에 한정한 파일럿으로는 설득력이 있지만, 운영 우위나 재현 가능한 비교로 확장하기에는 근거가 부족하다.

## 2. 점수

- 독창성: **3/5** — 승인된 문서 링크 후보에 구조화 판단 모델과 LLM의 품질·비용·보정을 비교한 적용 기여는 유용하다. 새로운 링크 구성 또는 검색 알고리즘을 제안하지 않고 기존 pair·choice·list 형식의 비교에 머문다.
- 기술적 타당성: **3/5** — 판정기가 같은 후보를 보고 고정 임계값을 사용하며, pair·choice·list의 출력 형식 차이도 명시한다. 다만 승인 링크만 양성인 불완전 gold이므로 precision과 ECE는 실제 관련성의 검증값이 아니라 현재 그래프와의 일치도다.
- 실험 설계·근거: **3/5** — 3회 호출 산포와 36개 링크 기록·77개 음성 슬라이드의 paired 군집 부트스트랩을 분리한 점이 적절하다. 단일 도메인·작은 표본이며 K=50 LLM pair, K=100 반복, K=50 downstream 및 downstream 반복은 완료되지 않았다.
- 관련 연구 위치짓기: **3/5** — RAG, GraphRAG/KG-RAG, 관계 추출, 법률 상호참조, 보정 및 cascade를 연구 질문과 연결한다. 인용 순서는 본문 최초 출현 순서와 참고문헌 순서가 일치하고, 확인한 서지 항목에서도 뚜렷한 오류는 찾지 못했다.
- 명확성·작성: **3/5** — 평가 단위, candidate-missing gold 처리와 결과 한계가 이전보다 분명하다. 초록의 비용 표현은 3회 합계와 평균을 혼동할 수 있고, 방법·수치가 촘촘해 일부 문장은 한 번 더 다듬을 필요가 있다.
- 양식 준수(KIISE 2~3쪽, 익명성): **3/5** — DOCX 구조에서 A4, 제목 단단·본문 2단, 빈 작성자·최종 편집자 메타데이터와 본문 저자 표기는 확인했다. 다만 docProps/app.xml의 2쪽·281단어 정보는 실제 본문 분량을 반영하지 않는 것으로 보여 페이지 수와 표 잘림은 제출 PDF로 확인해야 한다.
- 재현성: **2/5** — API 모델 ID/응답 모델, 실행 시각, seed, OpenAI 요청 설정과 프롬프트 SHA-256을 기록했다. 그러나 코드 commit과 원본 DB/승인 링크 snapshot hash가 없고 프롬프트 목록은 논문에 포함된 보충자료나 고정 저장소 링크가 아니라 내부 재분석 파일에 있다.

**종합 점수: 2/5**

**판정: Weak Reject** — Round 1에서 요구한 비용·불확실성·downstream 보고는 상당히 개선됐으며 결론도 파일럿으로 제한한다. 하지만 초록의 비용 단위와 실행 재현 artifact가 아직 불명확하고, 승인 graph와의 일치도만으로는 실제 링크 정확성이나 다른 도메인에서의 유용성을 뒷받침할 수 없다.

## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **위치: 초록 및 §3.2 표 2 — 비용과 지연의 집계 단위를 일치시킬 것.**

   **문제:** 초록은 Jev choice의 “평균 비용”으로 USD 0.121470과 129.75초를, LLM pair의 수치로 USD 0.726212와 668.05초를 제시한다. 그러나 표 2와 paper_jev/experiments/summary/cost_latency.json 및 paper_jev/experiments/summary/round2/round2_tables.md의 값은 K=10 **세 반복의 합계**다. 현재 표현은 반복당 평균으로 오독될 수 있다.

   **수정 요구:** 초록에서 “3회 합계”임을 밝히거나 금액·시간을 3으로 나눈 반복당 평균을 제시하라. 표 2에는 현재 합계와 반복당 값 중 무엇인지 분명히 표시하고, 두 판정기의 비용 비교가 같은 3회 실행 범위임을 유지하라.

2. **위치: §3.2 재현성 문장 및 보충자료 — 실행 입력의 불변 식별자를 제공할 것.**

   **문제:** 초안은 “프롬프트 파일과 SHA-256은 재분석 부록에 있다”고 하지만, 파일 목록과 hash는 현재 paper_jev/experiments/summary/round2/round2_tables.md에 있고 제출 문서에서 찾을 고정 보충자료 위치가 명시되지 않았다. 초안도 코드 commit과 원본 DB snapshot hash를 기록하지 못했다고 인정한다. 실행 시각·모델 alias·seed를 밝혀도 코드와 승인 링크 입력이 바뀌면 같은 결과를 재구성하기 어렵다.

   **수정 요구:** 프롬프트 원문과 hash, 코드 commit(또는 고정 아카이브), 평가에 사용한 입력 DB/승인 링크 snapshot의 hash를 익명 심사자가 열람할 수 있는 보충자료로 묶고 본문에서 위치를 가리켜라. 과거 snapshot을 특정할 수 없다면 그 한계를 재현성 주장에 반영하고, 결과를 보존된 응답 cache에서 재산출한 분석으로 한정하라.

## 4. 고치면 좋은 점 (Should-fix)

- **위치: §3.1 표 1·§4 결론:** precision·ECE와 false positive가 사람 검증된 정답이 아니라 현재 승인 graph와의 일치라는 표현을 해석 문장에서도 일관되게 유지하라. 미승인 후보 40건의 사람 검토가 비어 있으므로, 승인 링크 기준 ECE를 실제 확률 보정으로 일반화하지 말라.
- **위치: §3.1 형식 패리티 및 초록:** pair/choice/list는 판정 모델과 출력 형식이 함께 달라진다. 현재 §3.1에서 이 한계를 인정한 점은 적절하다. 초록과 결론에서도 이를 모델 자체의 우열이 아니라 해당 운영 형식의 비교로 읽히게 유지하라.
- **위치: DOCX 제출본:** 제목 구역은 1단, 본문은 2단, A4 및 작성자 메타데이터 비움은 확인했다. paper_jev/drafts/round2_draft.docx의 2쪽 속성만으로는 실제 쪽수를 입증할 수 없으므로, KIISE 제출 PDF를 렌더링해 실제 2~3쪽인지와 표·참고문헌 잘림 여부를 확인하라.
- 본문 인용 [1]–[11]은 처음 등장하는 순서로 배열되어 있고 가격·API 항목에는 URL과 조회일이 기재돼 있다. 최종 PDF에서도 번호 순서와 URL의 줄바꿈이 유지되는지 확인하라.

## 5. 추가 실험 제안

API 크레딧이 회복되면 K=10 downstream을 추가 반복해 단일 r1 실행의 변동을 제시하고, K=50 best-link downstream을 실제로 평가하라. 별도로 paper_jev/data/fp_review_checklist.csv의 고확률 미승인 후보를 도메인 검토자 두 명이 독립 판정하고 불일치 조정·일치도를 기록하면, 승인 graph와의 일치 지표를 실제 관련성 precision과 구분하는 데 가장 직접적인 도움이 된다. 현재는 이 사람 검토와 크레딧이 완료되지 않았지만 초안이 해당 결과를 파일럿으로 한정하므로, 완료되지 않은 비교를 이번 판정의 별도 요구로 삼지는 않는다.

## 6. 이전 라운드 지적 반영 여부

- **C1 비용·지연 집계 — 반영:** K=10 표에 호출 수, 입력·cached input·출력 토큰, 가격과 조회일, 세 반복 합계 비용 및 순차 API 시간, cascade 단계별 비용을 넣었다. K=50 cascade의 증분 USD 1.209444와 K=10 Jev 재사용을 포함한 누적 USD 1.601804도 구별했다. 초록의 “평균”만 합계 단위에 맞춰 수정해야 한다.
- **C2 API 요청·실행 설정 — 부분 반영:** jev-latest와 응답 jev-1.13.0, gpt-5.6-luna, 실행 시각, JSON/temperature 0, seed와 프롬프트 hash를 제시했다. 코드 commit과 원본 DB snapshot hash는 여전히 없으며, hash 표는 제출물 안의 고정 보충자료로 연결되지 않았다.
- **C3 downstream 링크·평가 설정 — 반영:** 세 반복의 p≥0.5 다수결 링크, GPT-5.6 Luna 및 text-embedding-3-small, 37개 질의 중 via_link가 있는 20개, 변형별 r1 단일 실행을 밝혔다. 단일 실행임을 결과의 탐색적 한계로 명시했다.
- **C4 반복 산포와 일반화 — 반영:** 세 API 반복의 표준편차와 링크·음성 슬라이드 cluster bootstrap 구간을 구분하고, bootstrap도 단일 자료의 표집 변동이지 도메인 일반화 근거가 아님을 밝혔다. 결론을 불완전 gold·한 도메인의 파일럿 비교로 한정했다.
