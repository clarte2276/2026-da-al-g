# KIISE 프로그램위원회 심사 의견 (Reviewer B, Round 4)

## 1. 요약

1. 본 논문은 서울 6호선 운전 규정과 현장 길라잡이 사이의 관리자 승인 구간 링크를 확장 경계로 쓰고, 연결 근거만 질문별로 재정렬하는 검색 파이프라인을 평가한다.
2. 6개 변형의 18개 완주 실행에서 `link_all`과 `proposed`는 `hybrid_rerank`보다 그래프 `Recall`을 0.264, 0.253 높여, 링크 확장을 주기여로 재배치한 비교는 설계상 타당하다.
3. 다만 그래프 사례 중 15건은 선정된 링크와 양쪽 원문을 바탕으로 LLM이 초안했고 미검수 상태이며, 답변 정확도 차이도 확인되지 않아 결과는 탐색적이다.

## 2. 점수

- 독창성: **3/5** — 승인 링크를 운영상 경계로 쓰는 문제 설정은 구체적이나 검색·재정렬 구성은 기존 요소의 조합이다.
- 기술적 타당성: **3/5** — 직접 근거 보존과 연결 근거 재정렬은 일관되지만 링크 승인·갱신의 품질 기준이 정의되지 않았다.
- 실험 설계·근거: **2/5** — 비교 실행은 완결됐으나 핵심 그래프 결과가 링크 기반으로 작성된 미검수 사례에 크게 의존한다.
- 관련 연구 위치짓기: **3/5** — KG²RAG·CARAG·철도 RAG와의 차이를 설명했지만 직접 비교로 기여를 분리하지는 못했다.
- 명확성·작성: **3/5** — 방법과 한계는 명료하지만 출처별 결과보다 혼합 표본의 효과가 앞서 부각된다.
- 양식 준수(KIISE 2~3쪽, 익명성): **4/5** — 초안 README의 렌더링 기록상 3쪽이며, DOCX 작성자 메타데이터가 비어 있고 제목 메타데이터도 정상이다.
- 재현성: **3/5** — 평가셋·모델·임베딩·반복 조건은 제시했으나 실행 당시 링크 스냅샷과 재정렬 프롬프트가 없다.

**종합 점수: 2/5**

**판정: Weak Reject** — 링크 확장과 선택 재정렬의 비교는 완결됐지만, 독립적으로 검수된 시험 자료가 없어 성능 개선을 제출 가능한 근거로 인정하기 어렵다.

## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **위치: §3 표 3, §4 결론 및 초록. 표본 출처에 따른 링크 효과 분리.**

   `existing_v2` 그래프 5건은 개발 자료이고 `llm_drafted` 그래프 15건은 서로 다른 승인 링크를 먼저 고른 뒤 그 양쪽 원문에서 질문·답을 작성했다. 검색 결과를 사용해 질문을 조정하지 않았다는 점은 긍정적이나, 평가 대상 자체가 링크를 중심으로 구성되어 일반 현장 질의의 표본을 대표한다고 보기 어렵다. 집계표에서도 `proposed`−`hybrid_rerank` `Recall` 차이는 신규 15건에서 0.2667 (p=.0039), 기존 5건에서는 0.2111 (p=.1250)이며, 기존 집합은 검정력이 매우 낮다. 현재 본문은 이 두 집합을 합친 20건의 차이를 초록·결론의 대표 결과로 제시한다. 두 집합의 paired 효과와 표본 수를 본문에 나누어 싣고, 신규 사례의 질문·정답·필수 근거 및 양쪽 링크 끝점을 규정 실무자 두 명이 독립 검수한 뒤 불일치 조정·수정 건수·일치도를 보고하고 지표를 다시 계산하라. 답변 품질을 해석하는 경우에는 생성 답변도 변형명을 가린 상태에서 독립 평가하라. 검수가 불가능하면 15건 결과는 링크 조건에 맞춘 파이프라인 점검으로만 표시하고 일반 질의에서의 개선을 주장하지 말라. 근거: `paper/data/README.md`, `paper/data/human_review_checklist.md`, `paper/experiments/summary/main_table.md`, `paper/experiments/summary/notes.md`.

2. **위치: §3 표 3 및 결과 해석. 사례 간 의존성을 반영한 불확실성.**

   본문은 20개 사례를 짝지어 부트스트랩 CI와 Wilcoxon p값을 제시하고, 다중 비교 보정 전 탐색값이라고 밝힌다. 그러나 집계 노트는 여러 사례가 같은 규정이나 링크를 공유할 수 있다고 명시한다. 따라서 사례를 독립 재표집 단위로 둔 CI와 signed-rank 검정은 불확실성을 작게 잡을 수 있다. 규정 조항 또는 링크 관계 단위의 군집을 반영해 재분석하고, 현재 자료로 이를 안정적으로 추정할 수 없다면 p값을 확증적 증거로 읽지 않도록 표와 결론을 기술통계 중심으로 낮춰라. 근거: `paper/experiments/summary/notes.md`, `paper/experiments/summary/main_table.md`.

3. **위치: §2 방법, §3 재현 조건. 승인 링크 집합과 재정렬 설정의 추적.**

   링크가 평가 시점의 공유 DB 상태를 따라가지만, 논문에는 실행에 사용된 스냅샷 식별자가 없고 방법 설명에도 승인 주체·기준과 재정렬 프롬프트 버전이 없다. 평가 자료 안내는 현재 DB에서 승인 링크 36개를 확인했으며 신규 그래프 사례에는 이 중 15개를 사용했다고 기록한다. 이 조건에서는 같은 평가셋·모델만으로 결과를 재현하거나 “사람 승인”의 의미를 검증하기 어렵다. 본문 또는 공개 보충자료에 링크 ID 집합의 고정 스냅샷·해시, 승인 기준과 담당 역할, 재정렬 모델·프롬프트 버전을 기록하라. 당시 스냅샷을 복원할 수 없다면 그 한계를 재현성 한계로 명시하고, 승인 상태 자체를 링크 품질 검증으로 해석하지 말라. 근거: `paper/drafts/round3_draft.md`, `paper/data/README.md`, `paper/data/human_review_checklist.md`, `paper/experiments/summary/notes.md`.

## 4. 고치면 좋은 점 (Should-fix)

- **§3–4 선택 재정렬의 해석:** 링크 확장과 달리 `proposed`가 `link_all`보다 낫다는 근거는 제한적이다. `Recall` 차이는 −0.011 (p=.750), 링크 정답 `Recall`은 −0.042 (p=.500), `Context Precision`은 +0.046 (p=.067)이고 답변 정확도 차이도 −0.002 (p=.622)다(`paper/experiments/summary/main_table.md`). 현재처럼 부차 기여로 한정하되, 본문 논의에도 다른 지표의 비유의 차이를 함께 제시해 `Context Precision` 추세가 단독 성능 향상처럼 읽히지 않게 하라.
- **§3 운영 비용:** 추가 재정렬 호출이 응답 지연과 비용에 미치는 영향을 보고하라. 집계 결과에 검색 지연이 있으나 본문에는 지연·토큰 비용이 없어, 선택 재정렬의 품질 절충을 운영 관점에서 판단하기 어렵다(`paper/experiments/summary/main_table.md`).

## 5. 추가 실험 제안

결론을 바꿀 수 있는 실험은 링크 그래프를 보지 않은 철도 규정 실무자가 실제 질의 또는 독립 작성 질의로 holdout을 만들고, 다른 두 검수자가 필수 근거를 확정한 뒤 `hybrid_rerank`, `link_all`, `proposed`를 동일 조건으로 세 번 비교하는 것이다. 생성 답변은 변형명을 가린 상태에서 절차 정확성과 근거 적합성을 평가하라. 기대 노력은 질의·라벨 작성과 검수에 약 2–3인일이며 API 사용량은 별도다.

## 6. 이전 라운드 지적 반영 여부

- **개발 자료와 신규 자료 분리 — 반영.** `existing_v2`와 `llm_drafted`를 구분하고 결과를 별도로 집계했다.
- **미완료 기준선과 TODO — 반영.** 6개 변형 모두 37건을 r1–r3에서 완주해 이전의 `hybrid_rerank` 미실행과 `link_all` 부분 실행 문제를 해결했다.
- **신규 사례 검수 및 출처별 통계 — 부분 반영.** 미검수 상태와 링크 기반 사례 생성을 공개했지만 사람 검수는 없고, 출처별 비교는 요약 자료에만 있으며 본문은 혼합 20건의 paired 결과를 대표로 제시한다.
- **통계 단위와 다중 비교 — 부분 반영.** paired 절차·짝 수·비영 차이 수·보정 전 p값을 설명했다. 다만 사례 간 링크·규정 공유 가능성을 밝힌 것만으로 군집 의존성에 따른 불확실성이 해결되지는 않았다.
- **관련 연구와 기여 범위 — 대부분 반영.** KG²RAG, CARAG, 철도 RAG 및 LegalBench-RAG와의 구별을 추가하고 일반 그래프 알고리즘 우월성 주장을 피했다. 다만 운영 설계와 알고리즘 기여의 경계는 실험적으로 검증되지 않았다.
- **재현성 및 judge 편향 — 부분 반영.** 평가셋, 모델·임베딩, 동일 생성·평가 judge 사용을 밝혔다. 승인 링크 스냅샷, 승인 절차, 재정렬 프롬프트와 독립적인 답변 평가는 남아 있다.
- **안전 경계 — 반영.** 오프라인 근거 검토에 한정하고, 연결 근거가 빠져도 경고 없이 직접 근거만으로 답할 수 있음을 공개했으며, 안전성 검증 전 운전 판단에 사용하지 말라고 적었다.
- **KIISE 형식과 문서 메타데이터 — 반영.** DOCX는 README의 렌더링 기록상 3쪽으로 2–3쪽 범위에 있고 익명 작성자 정보를 유지한다. 본문 인용 순서도 정리됐으며 제목 메타데이터는 현재 정상이다. 근거: `paper/drafts/README.md`, `paper/drafts/round3_draft.docx`.
