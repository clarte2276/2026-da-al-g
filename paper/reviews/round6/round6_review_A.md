# KIISE 심사 의견 — Round 6, Reviewer A

## 1. 요약

1. 본 논문은 철도 규정과 현장 길라잡이 사이에 관리자가 승인한 문서 구간 링크를 따라 검색 근거를 확장하고, 연결 근거만 추가로 재정렬하는 방식을 평가한다.
2. 일곱 검색 변형을 37개 질문에서 각각 세 차례 실행하고, 기존 사례 17건과 링크 기반 생성 사례 20건을 나눠 검색·답변 지표를 제시한다.
3. 생성 사례 20건을 현업 전문가 한 명이 검수했으나 그래프 질문 15건은 평가 대상 링크에서 출발했고 기존 그래프 질문 5건도 개발 사례이므로, 일반 현장 질의의 성능 향상으로 읽을 근거는 부족하다.

- **기술적 타당성: 3/5** — 직접 근거를 보존하고 연결 근거만 선별하는 절차는 일관되나, 승인 기준과 문서 변경 시 링크 관리 규칙은 정의되지 않았다.
- **실험 설계·근거: 2/5** — 라벨 검수는 진전됐지만 평가 표본이 링크 구성에 조건화되어 있고 독립 holdout이 없다.
- **관련 연구 위치짓기: 3/5** — KG²RAG, CARAG, 도시철도 출입문 RAG와의 차이를 소개했으나 직접 비교로 기여를 분리하지는 못했다.
- **명확성·작성: 4/5** — 방법·결과·한계가 짧은 지면에 대체로 명료하게 정리돼 있다.

**종합 점수: 2/5**

**판정: Weak Reject** — 완결된 비교와 전문가 검수는 이전 버전보다 낫지만, 핵심 성능 주장이 링크를 미리 선택해 만든 평가 사례에 의존한다.

## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **위치: 초록, §3 평가셋 설명·표 2, §4 결론. 평가 표본의 독립성 한계에 맞춰 주장을 제한할 것.**

   **문제:** 신규 그래프 사례 15건은 서로 다른 승인 링크를 하나씩 정하고 그 양 끝 원문에서 질문·답·gold를 작성했다. 검색 결과를 보지 않고 만들었다는 점은 장점이지만, 이 표본은 여전히 평가 대상 링크를 전제로 한다. 이 사례들의 Recall 차이는 링크 구조가 있는 문항에서 그 링크를 따라간 효과를 보여줄 뿐, 링크 활용이 실제 현장 질의에서 일반적으로 유효하다는 증거는 아니다. 새 사례 20건의 검수도 링크 구조를 알고 있는 현업 전문가 한 명의 체크리스트 검수였으며, 기존 그래프 사례 5건은 개발 자료다. 따라서 어느 집합도 독립적인 현장 holdout은 아니다. 근거: `paper/data/README.md`, `paper/data/human_review_checklist.md`, `paper/data/human_review_record.md`, `paper/reviews/round4/round4_summary.md`.

   **수정 요구:** 새 실험 없이 현재 결과를 제출하려면 초록과 결론에서 이를 “링크를 전제로 구성한 사례에서의 검색 파이프라인 점검”으로 한정하라. §3에 사례 출처와 군집 수를 붙여 쓰고, 기존 5건과 생성 15건을 합쳐 일반적인 링크 효과를 뒷받침하는 표현은 피하라. `link_all`−K3의 생성 사례 Recall 차이 +0.267은 해당 구성 사례에서의 기술 통계로 제시할 수 있지만 독립 표본에서 재현된 효과처럼 서술해서는 안 된다(`paper/experiments/summary/main_table.md`).

2. **위치: §3 표 2·3, §4 결과 해석. 군집 수가 작은 구간 추정의 의미를 더 분명히 할 것.**

   **문제:** 끝점 군집 부트스트랩의 10,000회 반복은 사례의 종속성을 고려하려는 적절한 시도지만, 기존 사례는 5개, 링크 기반 생성 사례는 6개 군집뿐이다. 이 정도의 독립 군집 수에서 percentile 95% 구간은 표본 구성 하나에 민감해 안정적인 추론 구간으로 보기 어렵다. 예를 들어 `link_all`−K3 Recall 구간은 기존 사례에서 [+0.017, +0.244], 생성 사례에서 [+0.083, +0.440]으로 양수지만, 군집 수가 적다는 점을 감안하면 효과를 확정하는 근거가 되지 않는다. 논문은 이를 탐색적으로 해석한다고 적었으나 표의 “95% 신뢰구간”은 강한 추론으로 오독될 수 있다. 근거: `paper/experiments/summary/notes.md`, `paper/experiments/summary/main_table.md`.

   **수정 요구:** 기존 결과로 군집별 차이 범위 또는 한 군집씩 제외한 민감도 분석을 제시하고, 5·6개 군집에서 계산한 bootstrap 구간은 기술적 민감도 결과라고 표와 결론에서 분명히 하라. 이를 다시 계산하기 어렵다면 구간을 효과 확정 근거처럼 읽히지 않게 표의 표제·본문을 조정하고, 사례 수와 독립 군집 수를 함께 표시하라. 새 표본을 수집하거나 새 실행을 요구하는 항목은 아니다.

3. **위치: §2 방법, 초록·§3 비교 결과, §4 결론. K3 비교가 검증하는 범위를 정확히 말할 것.**

   **문제:** K3는 재정렬 결과가 3개 미만인 경우에만 근거를 보충하는 설정이라 정확한 근거 수나 토큰 예산을 고정하지 않는다. 그래프 질의의 평균 근거 수는 K3 3.15개, `link_all` 3.08개, `proposed` 3.00개로 비슷하지만 문맥 길이와 비용은 통제되지 않았다. 따라서 `link_all`·`proposed`와 K3의 차이는 승인 링크의 효과만을 분리한 결과가 아니라 서로 다른 전체 검색 경로의 차이다. 본문은 이를 토큰 예산 통제 실험이 아니라고 밝혔지만, 초록의 대표 Recall 차이를 링크 확장 자체의 효과로 읽을 여지가 남는다. 근거: `paper/experiments/README.md`, `paper/experiments/summary/main_table.md`, `paper/final/final_draft_v2.md`.

   **수정 요구:** 현재 결과로 제출하려면 초록·결론의 차이를 “이 평가 조건에서 K3보다 링크 확장 파이프라인이 더 많은 gold를 회수했다”로 한정하고, 승인 링크만의 인과 효과나 정확한 동일 예산 비교로 표현하지 말라. 표와 문장에 최종 근거 수 평균을 함께 두고 K3가 최소치 기준선임을 유지하라. 엄밀한 예산 통제 결과가 필요한 경우는 §5의 후속 실험으로 분리한다.

## 4. 고치면 좋은 점 (Should-fix)

- **§3·§4 — 선택 재정렬의 효용:** 생성 사례에서 `proposed`−`link_all` Recall 차이는 −0.022, 링크 정답 Recall 차이는 −0.067이고, Context Precision은 +0.025, Answer Correctness는 −0.001이다(`paper/experiments/summary/main_table.md`). 선택 재정렬은 부차 분석이라는 현재 위치를 유지하고, 답변 품질이나 전반적인 검색 성능이 개선됐다는 인상을 주지 않게 하라.
- **§3 답변 평가:** 생성 모델과 RAGAS judge가 모두 `gpt-5.6-luna`이며 블라인드 사람 평가는 없다. K3 답변 지표도 r1 한 번만 있다. 답변 점수는 자동 judge의 탐색 결과로 한정하고, 사람 평가 없이 절차 정답성을 확인한 것처럼 쓰지 말라(`paper/experiments/summary/notes.md`, `paper/final/final_draft_v2.md`).
- **§2·§4 재현성:** 스냅샷과 프롬프트 해시 기록은 보강됐으나, 관리자가 어떤 근거로 링크를 승인하는지와 문서 개정·폐기 때 무엇을 하는지는 여전히 확인되지 않았다(`paper/experiments/provenance.md`). 이 정보를 독자가 접근할 수 있도록 익명 보충자료에 제공하고, 승인 상태가 의미적 품질 검증을 뜻하지 않는다는 현재 한계를 유지하라.

## 5. 추가 실험 제안

결론을 바꿀 수 있는 실험은 링크 목록을 먼저 보지 않은 상태에서 만든 실제 운전·정비 질의 20~30건으로 독립 holdout을 구성하는 것이다. 두 명의 현업 전문가가 질문·정답 근거를 독립 확인하고, 링크의 양 끝이 실제로 필요한지도 판정한다. 그 뒤 `hybrid_rerank_k3`, `link_all`, `proposed`를 같은 평가셋에서 비교하고, 최종 문맥 토큰 예산을 맞춰 답변을 변형명 가림 상태로 채점한다. 링크를 미리 택하지 않은 표본에서도 검색 이득이 남고 절차 답변이 나아지는지에 따라 결론이 달라질 수 있다. 사례 작성·검수·맹검 채점에 약 3~5인일과 별도 API 비용이 들 것으로 본다.

## 6. 이전 라운드 지적 반영 여부

- **반영:** round1·2에서 지적한 미실행 기준선과 불완전한 실행은 해소됐다. 일곱 변형이 모두 37건을 세 차례 평가했고, K3 최소 근거 수 비교도 추가됐다(`paper/experiments/summary/notes.md`).
- **반영:** 관련 연구를 KG²RAG, CARAG, 도시철도 출입문 RAG 등으로 보강했고, 기존 사례와 신규 사례를 출처별로 나눴다. 링크 스냅샷·해시와 재정렬 프롬프트 해시도 `provenance.md`에 기록됐다.
- **부분 반영:** round1·2·4가 요구한 신규 라벨 검수는 현업 전문가 1인의 20/20 체크리스트 검수로 진행됐고 수정·삭제는 없었다. 이는 출처 사실성과 문항 타당성 확인에 도움이 되지만, 블라인드 독립 검수나 평가자 간 일치도는 제공하지 않으며 링크 기반 표본의 독립성 문제도 해소하지 않는다.
- **부분 반영:** 출처별 짝 비교와 끝점 군집 부트스트랩은 추가됐고, 표본이 작다는 경고도 있다. 다만 추론에 쓸 수 있는 군집은 기존 5개·생성 6개여서 효과를 확정하기 어렵다.
- **미반영:** 승인 기준 및 문서 개정·폐기 절차, 링크를 미리 선정하지 않은 holdout, 답변에 대한 독립적인 블라인드 사람 평가는 아직 없다. 따라서 실제 현장 효용·안전성에 관한 주장은 현재 자료 범위로 제한해야 한다.
- **형식:** round2·4의 페이지 배치 우려는 현재 PDF에서 해소된 것으로 보인다. 세 쪽 모두 읽을 수 있고, 표와 본문이 겹치거나 잘린 부분은 없으며, 페이지에 저자 이름·소속이 표시되지 않는다.

   **제안:** “본 연구에서는 관리자가 승인한 규정·길라잡이 구간 링크로 검색 결과를 확장했을 때의 효과를 평가한다.”

8. **§3 원문:** “평가 시점의 승인 링크 스냅샷은 36개 행으로 구성되며, 해시는 재현용 기록에 보관했다.”
