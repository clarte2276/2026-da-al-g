# Round 1 리뷰 — Reviewer A

## 1. 요약

1. 본 연구는 서울 6호선 운전 규정과 현장 길라잡이 사이의 담당자 승인 링크를 따라 근거를 최대 2 hop 확장하고, 연결 근거만 질문별로 재정렬하는 Graph RAG를 제안한다.
2. 37개 평가 사례에서 제안법을 3회 완전 실행했으며, 그래프형 검색 Precision/Recall은 0.742/0.839, Context Precision/Recall은 0.923/0.916으로 보고한다.
3. 비교군 link_all은 부분 실행이고 주요 검색 기준선은 미완료라, 현재 결과는 선택적 확장의 우월성보다 제한된 사례에서의 탐색적 비교를 뒷받침한다.

## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **§4 실험 설계 및 결론 — 튜닝 자료와 평가 자료의 분리**: `paper/data/README.md`는 v3가 기존 v2 사례 17건(문서형 12건, 그래프형 5건)을 보존한다고 설명한다. 한편 `docs/rag-pipeline.md`는 v2 평가 결과를 기록하고 `top_k`, reasoning effort, 답변 지시문과 링크 재정렬 변경의 근거로 든다. 그러므로 현재 결과에는 방법 선택에 사용된 사례가 재등장한다. 두 문서의 v2 문서형 사례 수 설명도 일치하지 않으므로, v2와 v3의 사례 ID 및 중복 수를 먼저 명시하고 과거 튜닝 사례는 개발 자료로 분리해야 한다. 최종 효과 주장은 튜닝에 쓰지 않은 별도 holdout에서 확인하고, 새 시험셋을 마련하지 못하면 중복 사례와 신규 사례 결과를 분리해 제한적으로 보고하라.

2. **§4 평가셋·정답 근거 — LLM 초안 라벨의 사람 검수**: `paper/data/README.md`와 `paper/data/human_review_checklist.md`에 따르면 새로 만든 20건(문서형 5건, 그래프형 15건)의 질문·답변·근거 라벨은 LLM 초안이며 검수가 남아 있다. 특히 그래프형은 양쪽 문서 끝점이 모두 답에 필요한지를 검증해야 한다. 두 명 이상의 검수자가 원문과 근거를 독립 확인하고, 불일치 조정 절차와 일치도를 보고한 뒤 확정 라벨로 전 지표를 다시 계산하라. 검수 전 수치는 파일럿으로 표시하고 성능 결론의 근거로 취급하지 말라.

3. **표 1–2 및 §4 기준선 비교 — 동일 조건의 완결 실행**: `paper/experiments/summary/notes.md`는 dense, hybrid, hybrid_rerank의 r1–r3가 모두 없고, BM25는 검색 전용 r1만 있다고 기록한다. `link_all`도 반복별 31/37, 35/37, 31/37 사례만 완료한 반면 제안법은 37/37을 세 번 완료했다. 따라서 표의 TODO를 채우고 BM25·dense·hybrid·hybrid_rerank·link_all·제안법을 같은 사례와 동일한 생성·채점 조건으로 반복 실행하라. 특히 hybrid_rerank는 링크 확장 자체의 효과를 분리하는 비교군이다. API 한도로 완료가 불가능하면 현재 표를 파일럿으로 한정하고, 부분 교집합 비교로 일반적인 우월성을 주장하지 말라. 근거: `paper/experiments/summary/notes.md`, `paper/experiments/summary/main_table.md`.

4. **§4 통계 및 지표 정의 — 불균형 반복과 다중 비교를 드러낼 것**: `paper/experiments/summary/main_table.md`의 paired 비교는 사례별로 가용 반복을 평균한 뒤 비교하며, link_all은 일부 사례가 세 번보다 적게 측정됐다. 전체 Context Precision 비교의 `n=35`는 짝지은 사례 수이고 exact Wilcoxon 검정에서 0차이를 제외한 수는 20이다. 또한 집계표에는 3개 범주 × 9개 지표의 27개 비교가 있어 본문 `p=0.0047`은 다중 비교 보정 전 값이다. 사례마다 동일한 반복 수를 확보하고 효과 크기·불확실성·전체 짝 수와 비영 차이 수를 함께 표시하라. 보정된 p값을 제시하거나 모든 p값을 보정 전 탐색 결과라고 명시하라. `paper/experiments/README.md`의 실제 매칭 규칙은 문서 버전과 조항 번호 또는 페이지 일치이며, precision 분모는 최종 근거 수다. 본문의 “문서 조각 단위” 표현을 이 규칙, 가변 근거 수, 각 지표의 계산 단위와 일치시켜라.

## 4. 고치면 좋은 점 (Should-fix)

- **§2 관련 연구**: `paper/references/related_work.md`가 정리한 KG²RAG, CARAG, 도시철도 출입문 장애 RAG를 우선 인용하고, seed 기반 그래프 확장 및 철도 QA 선행연구와 방법·평가 단위별로 비교하라. 현재 GraphRAG와 LegalBench-RAG만으로는 가장 가까운 연구와의 기여 경계를 판단하기 어렵다.
- **§4 재현성**: 검색 임베딩, 답변 생성기, RAGAS 버전, 채점 모델·프롬프트, 반복 간 바뀐 조건을 명시하라. “같은 계열 LLM judge”만으로는 답변 점수의 변동과 재현성을 해석하기 어렵다.
- **§4 실용성**: 집계 결과에서 제안법의 전체 검색 지연은 평균 2.323초, link_all은 1.816초다(`paper/experiments/summary/main_table.md`). 선택 재정렬의 지연·토큰 비용을 함께 보고해 정밀도 개선과 운영비용의 절충을 보여라.

## 5. 추가 실험 제안

튜닝과 겹치지 않는 사람 검수형 holdout에서 hybrid_rerank, link_all, 제안법의 답변 절차 정확도와 근거 인용 적합도를 익명·블라인드로 비교하라. 서로 다른 두 평가자가 사례별로 답변을 채점하고 불일치를 조정하는 실험은 새 데이터와 API 호출을 포함해 약 1–2 인일이 들 수 있으나, 자동 judge에 의존한 현재 결론을 바꿀 수 있는 가장 직접적인 검증이다.
