## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **위치: 2절 관련 연구, 1절 서론의 기여 설명.**

   **문제:** 본문은 RAG, LLM 재정렬, GraphRAG, LegalBench-RAG, RAGAS만 인용한다. 그러나 관련 연구 조사에는 seed 기반 그래프 확장 KG²RAG, 철도 운영·정비용 CARAG, 도시철도 출입문 조치 RAG 및 국내 철도 Graph RAG 발표가 정리되어 있다. 이들과의 차이를 보이지 않으면 “사람 승인 링크 + 선택 재정렬”은 기존 그래프 확장에 링크 필터를 더한 시스템 구성으로 읽히며, 신규 알고리즘 기여인지 도메인 적용 기여인지 판단하기 어렵다. (paper/drafts/round0_draft.md, paper/references/related_work.md의 11, 15–16, 28–29절)

   **수정 요구:** 가장 가까운 연구를 본문에서 직접 인용하고, 노드·링크 단위, 승인 주체와 기준, 질의별 링크 선택 규칙을 정의한 뒤 KG²RAG·CARAG와 방법 및 평가를 항목별로 비교하라. LegalBench-RAG의 전문가 gold 구간 주석과 본 연구의 실행 시점 링크 확장이 어떻게 다른지도 설명하라. 기술 차이가 제한적이면 기여를 새로운 Graph RAG 알고리즘이 아니라 철도 문서의 승인 링크 운영·평가로 좁혀 서술하라.

2. **위치: 4절 실험, 표 1–2, 5절 결론.**

   **문제:** 제안법은 매 회 37/37 사례를 평가했지만 link_all은 31/37, 35/37, 31/37만 완료했고, 그래프형도 19/20, 20/20, 19/20이다. dense, hybrid, hybrid_rerank는 미실행이고 BM25는 검색 전용 1회다. 따라서 선택 재정렬의 효과를 기존 hybrid rerank나 링크 전체 확장 대비 분리해 판단하기 어렵다. 보고된 그래프형 Context Precision 차이도 +0.0444, p=0.0673이며, 전체 교집합의 +0.0497, p=0.0047은 35개 사례 비교다. (paper/experiments/summary/notes.md, paper/experiments/summary/main_table.md, paper/drafts/round0_draft.md)

   **수정 요구:** 동일한 고정 평가셋과 설정으로 hybrid_rerank, link_all, proposed를 최소 3회 완전 실행하고, 가능한 경우 hybrid도 포함하라. 최소한 그래프형 20개 사례는 모든 변형·반복에서 짝을 맞춰야 한다. 완전 실행이 불가능하면 TODO 행을 결과처럼 남기지 말고, 현재 수치가 탐색적임을 표와 초록에서 분명히 제한하며 우월성 주장을 하지 말라.

3. **위치: 4절 실험의 평가셋 및 근거 라벨 설명.**

   **문제:** 평가셋 37건 중 신규 20건(문서형 5, 그래프형 15)의 질문·정답·근거 라벨이 LLM 초안이고 전부 사람 검수 전이다. 신규 그래프 사례는 승인 링크 36개 중 서로 다른 15개를 하나씩 사용했다. 정답 라벨 오류는 retrieval Precision/Recall과 답변 채점 모두에 영향을 주며, 현재 평가는 링크 집합의 일부만 반영한다. (paper/data/README.md, paper/data/human_review_checklist.md)

   **수정 요구:** 신규 20건을 원문과 대조해 운영 규정 전문가가 검수하고, 각 답변의 필수 근거와 링크 양끝이 실제 필요한지 확인하라. 가능하면 두 명이 독립 검수한 뒤 불일치를 조정하고 합의율을 보고하라. 본문에는 검수자 배경·절차와 36개 승인 링크 중 15개를 선택한 기준을 명시하고, 검수 후 점수를 다시 계산하라. 나머지 링크를 평가하지 않았다면 전체 링크 그래프에 대한 일반화는 주장하지 말라.

4. **위치: 4절 답변 평가 및 5절 한계.**

   **문제:** 결과 파일의 llm_model은 gpt-5.6-luna이며, 평가 스크립트도 같은 설정 모델로 RAGAS judge를 구성한다. 즉 생성 답변과 핵심 자동 평가는 같은 모델에 의존한다. 이 설정은 judge 편향 또는 모델 계열 선호가 제안법의 점수에 반영될 가능성을 배제하지 못한다. (paper/experiments/results/proposed_r1.json–proposed_r3.json, back/scripts/ragas_eval.py, docs/rag-pipeline.md)

   **수정 요구:** 답변 정답성과 연결 근거의 적절성을 운영 규정에 익숙한 사람 평가로 독립 검증하고, 평가자는 변형 이름과 모델 답변 출처를 모르게 하라. 별도 모델 judge를 민감도 분석으로 추가할 수 있으며, 본문에는 생성 모델과 judge의 정확한 모델 ID 및 동일 모델 사용 사실을 명시하라.

5. **위치: 3절 제안 방법, 4절 실험.**

   **문제:** 본문은 검색 가중치, 후보 수, hop 제한은 제시하지만, 정확한 생성·재정렬 모델, 프롬프트, 임베딩 모델, 디코딩 설정, 평가 구현 버전 및 실행에 사용한 승인 링크 스냅샷을 밝히지 않는다. 프로젝트 파이프라인 문서와 결과 파일에는 이 설정이 있으나, 논문만으로는 결과 조건을 재현하거나 링크 변경에 따른 차이를 추적하기 어렵다. (paper/drafts/round0_draft.md, docs/rag-pipeline.md, paper/experiments/results/proposed_r1.json)

   **수정 요구:** 본문 표 또는 공개 보충자료에 코드 커밋, 데이터셋 버전, 생성·평가 모델과 임베딩 모델, 재정렬 단계별 프롬프트·설정, 반복 조건, 링크 승인 기준과 스냅샷 식별자를 기록하라. 2–3쪽 제한 때문에 본문에 모두 싣기 어렵다면 재현 가능한 보충자료를 인용하라.

## 4. 고치면 좋은 점 (Should-fix)

- **1절 서론:** 일반 조항과 길라잡이의 분리가 어떤 실제 운전·정비 질의를 어렵게 하는지 짧은 사례로 보여 주고, 누가 답을 사용하며 어떤 결정을 지원하는지 설명하라. 현재 평가는 서울 6호선 단일 도메인의 오프라인 37문항이므로, 다른 노선으로의 일반화와 실제 기관사·관제사 현장 효용·안전성은 검증되지 않았다고 범위를 한정하라. (paper/drafts/round0_draft.md, paper/data/README.md, paper/data/human_review_checklist.md)
- **3절 제안 방법:** 승인 링크가 오래된 문서 버전, 충돌 규정 또는 폐지된 절차를 가리킬 때의 처리와 재검수 주체를 설명하라. 철도 운영 문서에서 링크 승인·갱신 비용은 시스템 실사용 가능성과 직접 관련된다. (paper/data/README.md, docs/rag-pipeline.md)
- **4절 표 1–2:** 평균 차이와 p값만으로 효과 크기를 판단하기 어려우므로 변형별 완전 사례 수, 사례 수준 분포 또는 신뢰구간을 간결하게 덧붙여라. 표의 TODO는 최종본에서 미실험으로 명시하거나 제거하라. (paper/experiments/summary/main_table.md, paper/drafts/round0_draft.md)

## 5. 추가 실험 제안

결론을 바꿀 수 있는 최소 실험으로, 사람 검수된 동일 그래프형 20문항에서 hybrid_rerank, link_all, proposed를 동일 모델 설정으로 3회씩 비교하라. 선택 재정렬의 개선이 재현되지 않거나 Answer Correctness가 더 낮아지면 본문의 기여·판정이 달라질 수 있다. 예상 노력은 평가 파이프라인 실행·정리 1–2인일이며, 신규 전문가 라벨 검수 시간은 별도다.
