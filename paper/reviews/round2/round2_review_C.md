# 2라운드 심사 의견 — 심사자 C

## 1. 요약

1. 본 논문은 서울 6호선 운전취급규정과 현장 길라잡이 구간 사이에 담당자가 승인한 링크를 두고, 이 링크를 이용해 철도 QA 근거를 확장하는 방식을 제안한다.
2. 직접 검색 근거는 보존하고 최대 2 hop 확장한 연결 근거만 다시 재정렬하며, 새 그래프형 사례 15건에서 검색·문맥 지표를 보고한다.
3. 저자는 새 라벨 미검수와 비교군 미완료를 명시하고 결과를 탐색적으로 한정하지만, 현재 근거만으로 선택 재정렬의 효과와 현장 안전성을 검증했다고 보기는 어렵다.

## 3. 반드시 고쳐야 할 점 (Must-fix)

1. **위치: §1 서론, §2 제안 방법, 참고문헌.**

   **문제:** 본문은 자동 그래프 생성 계열과 사람이 승인한 링크를 구분하고 KG²RAG·CARAG를 인용하지만, 제안 방법의 실질적 차이는 사람이 만든 엣지를 쓰고 확장 후 LLM으로 다시 거르는 구성에 머문다. 승인 주체·기준, 관계 종류, 링크가 구버전·상충 조항을 가리킬 때의 처리도 정의하지 않아 “human-approved”가 검증 가능한 방법 요소인지 단순한 데이터 관리 전제인지 판단하기 어렵다. LegalBench-RAG는 평가용 근거 주석이므로 이를 법률 RAG 전체와의 차별성 근거로 삼기에도 좁다. 관련 연구 조사에 포함된 한국어 법률 하이브리드 RAG도 본문 참고문헌에는 없다. (paper/references/related_work.md §8, §11, §13, §15, §24 및 종합표)

   **수정 요구:** 링크의 승인 주체·기준·문서 버전과 폐기 절차, 질의 시 선택 규칙을 짧게 정의하라. KG²RAG·CARAG와는 그래프 구성·확장·평가 차이를 직접 대조하고, LegalBench-RAG 및 한국어 법률 QA 연구는 평가 주석과 실행 시점 검색이 어떻게 다른지 구분하라. 이 차이를 실험으로 입증할 수 없다면 새 Graph RAG 알고리즘으로 읽히지 않도록 기여를 철도 문서 링크의 통제·운영 설계로 명확히 한정하라.

2. **위치: §3 평가셋 설명, 표 1–2, §4 결론.**

   **문제:** v3의 신규 20건(문서형 5, 그래프형 15)은 모두 LLM 초안이며 사람 검수 전이다. 신규 그래프 사례 15건은 승인 링크 36개 중 서로 다른 15개를 하나씩 골라, 선택된 길라잡이·규정 구간을 바탕으로 질문과 답을 만들었다. 따라서 이는 임의의 현장 질문 표본이 아니며, 사용한 링크 관계에 맞춘 평가 사례가 제안법에 유리할 가능성을 배제하기 어렵다. 현재 논문은 이 한계를 밝히지만, 미검수 gold에 대한 수치를 성능 근거로 해석할 수는 없다. (paper/data/README.md, paper/data/human_review_checklist.md, paper/experiments/summary/notes.md)

   **수정 요구:** 규정 실무자가 신규 질문·답변·근거 위치와 양쪽 링크 끝점의 필요성을 원문 대조해 검수하고, 수정 건수와 합의·조정 절차를 보고한 뒤 점수를 다시 계산하라. 검수가 불가능하면 표와 결론에서 해당 점수를 검증된 정확도처럼 제시하지 말고, 링크 사례에 대한 탐색적 파이프라인 점검으로만 해석하라. 15/36 링크 선택 기준도 밝히고 나머지 링크로 일반화하지 말라.

3. **위치: §3 표 1–2 및 paired 비교 결과.**

   **문제:** 제안법은 매 반복 37/37건을 완료했지만 link_all은 31/37·35/37·31/37건이고, 그래프형도 19/20·20/20·19/20건이다. hybrid_rerank는 미실행이라 링크를 쓰지 않는 재정렬과의 차이를 분리할 수 없다. 논문에 제시된 전체 집합의 Context Precision 차이 +0.0497, p=0.0047은 짝 35건에 개발 자료와 미검수 신규 자료, 문서형과 그래프형을 함께 포함하며 다중 비교 보정 전이다. 그래프형 20건의 p=0.0673도 신규 LLM 초안 15건만의 검정은 아니다. 본문에 탐색값이라고 한정했더라도 전체 집합의 유의한 p값은 선택 재정렬의 증거로 오독될 수 있다. (paper/experiments/summary/notes.md, paper/experiments/summary/main_table.md)

   **수정 요구:** 최소한 LLM 초안 그래프 15건에 대한 동일 사례 paired 차이를 별도로 보고하고, 반복별 누락으로 짝이 달라지는 범위를 표에 표시하라. 완결된 hybrid_rerank 기준선이 없다면 선택 재정렬의 우월성 검정으로 쓰지 말고, 현재 결과는 사례별 기술 통계와 제한된 교집합의 탐색 비교로만 제시하라. 전체 35건 p값은 개발·신규 및 문서·그래프 결과를 분리할 수 없다는 점을 바로 붙여 설명하거나 본문에서 제외하라.

4. **위치: §3 답변 평가, §4 한계 및 현장 사용 설명.**

   **문제:** 답변 생성과 RAGAS 평가가 같은 gpt-5.6-luna 모델이며, 신규 참조 답변도 LLM 초안이다. 따라서 답변 정확도와 문맥 점수는 서로 독립된 검증이 아니다. 논문은 현장 안전성 평가가 남았다고 적지만, 재정렬 실패·선택 결과 없음 시 링크 근거를 넣지 않는 동작이 규정상 필요한 특칙을 빠뜨릴 때 사용자에게 어떻게 표시되는지는 설명하지 않는다. 이는 기관사·관제원이 답을 운전 판단에 사용할 수 있다는 동기와 직접 연결된다. (paper/drafts/round1_draft.md §3–4, paper/data/README.md, docs/rag-pipeline.md §4)

   **수정 요구:** 기존 결과 답변을 변형 정보를 가린 상태로 규정 실무자가 확인해 절차 순서·수치·근거 인용의 오류를 기록하고, 독립 검수가 없으면 자동 judge 점수를 탐색 지표로 분명히 한정하라. 사용 시나리오를 오프라인 근거 탐색·검토 지원으로 제한하고, 링크 근거가 없거나 선택에 실패했을 때 불완전 답변임을 사용자에게 알리는 경계와 안전성 검증 전 운전 지시로 사용할 수 없다는 점을 명시하라.

5. **위치: §3 재현 조건.**

   **문제:** 평가셋 v3, 모델·임베딩·RAGAS 설정과 코드 기준 커밋을 추가한 점은 개선이다. 그러나 링크는 공유 DB의 승인 상태를 조회해 확장하고 데이터 안내도 DB 질의로 링크를 선정했다고 설명한다. 동일한 코드 커밋과 데이터셋만으로는 실행 시점의 링크 집합을 복원할 수 없으며, 두 차례 재정렬에 사용한 정확한 모델·프롬프트도 논문에 없다. (paper/drafts/round1_draft.md §2–3, paper/data/README.md, paper/experiments/README.md)

   **수정 요구:** 논문 또는 인용 가능한 보충자료에 승인 링크 스냅샷 ID·해시와 재정렬 모델·프롬프트 버전을 기록하라. 지면이 부족하면 불변 공개 산출물의 위치와 체크섬을 적어 독자가 같은 조건을 복원할 수 있게 하라.

## 4. 고치면 좋은 점 (Should-fix)

- **위치: §1 서론.** 기관사·관제원이 어떤 결정을 보조받는지 한 문장으로 구체화하고, 예를 들어 길라잡이의 SIV 조치와 규정의 보고 의무를 함께 확인하는 사례를 제시하라. 해당 예시가 실제 운전 지시가 아니라 근거 확인 지원이라는 경계를 함께 적으면 현장 동기와 안전 한계가 동시에 명확해진다. (paper/data/human_review_checklist.md의 graph_siv_start_failure)
- **위치: 표 1–2 주석.** ±가 반복 간 표준편차이고 사례 모집단의 신뢰구간이 아님을 표 가까이에 유지하라. 검색 지연 비교도 link_all의 부분 실행값임을 같은 주석에서 다시 밝혀, 평균 시간 차이를 완전한 비용 비교로 읽지 않게 하라. (paper/experiments/summary/main_table.md)
- **위치: §4 결론.** “정밀도와 문맥 정밀도가 더 높다”는 기술 통계 서술에는 신규 15건의 gold 미검수 상태와 낮은 표본 수를 같은 문장 안에서 연결해, 제한적인 수치 차이가 현장 성능 차이를 뜻하지 않음을 강조하라.

## 5. 추가 실험 제안

결론을 바꿀 수 있는 실험은 규정 실무자가 검수한 동일 그래프형 사례에서 hybrid_rerank, link_all, 제안법을 같은 조건으로 3회 비교하고, 생성 답변을 변형명 가림 상태에서 독립 채점하는 것이다. 특히 선택 재정렬이 Context Precision을 높이면서 필요한 특칙의 Recall·답변 절차 정확도를 유지하는지 확인해야 한다. 라벨·답변 검수와 실행·집계에 약 1–2인일이 들며 API 크레딧은 별도다. 이 차이가 재현되지 않으면 기여를 성능 개선이 아니라 링크 승인·추적 방식의 운영 사례로 한정해야 한다.
