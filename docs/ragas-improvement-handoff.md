## 1. 목표와 확정된 기준

사용자가 확정한 평가 기준:

| 평가 대상 | 완료 기준 |
| --- | --- |
| 문서 질문 17개 | Faithfulness, Answer Relevancy, Answer Correctness, Context Precision, Context Recall의 각 평균 ≥ 0.9 |
| 일반 지식 질문 4개 | Answer Correctness, Answer Relevancy의 각 평균 ≥ 0.9 |
| 인사말 | 자연스럽게 응답하고 문서 검색·근거 인용 없이 general로 처리 |
| 그래프 질문 5개 | 승인된 링크의 탐색·근거 추가를 검증하고, 답변에서 실제 활용됐는지 별도 확인 |

목표는 지표별 평균 기준이다. 케이스별 점수와 최저점도 보고하되, 모든 개별 점수가 0.9 이상이어야 한다는 추가 조건은 두지 않는다.

기존 인사말 포함 집계는 비교용으로 보존한다. 낮은 사례 삭제, 점수 보정, 평가 프롬프트 완화, 정답의 검색기 주입, 높은 결과만 선택하는 재시도는 하지 않는다.

## 2. 현재 상태와 검증 결과

작업은 중단됐으며, 담당 에이전트들이 실행하던 평가·검색 프로세스는 남아 있지 않다. 최신 코드의 전체 RAGAS 결과는 아직 없다.

이번 작업에서 반영된 변경:

* 원문 DocumentContent를 기준으로 청크 경계를 넘는 조문을 복원하고 중복을 통합했다.
* 복원된 근거에 UTF-16 위치 정보를 유지하며 Unicode 회귀 테스트를 추가했다.
* 한국어 어미 정규화를 보강했다.
* 넓은 그래프 연결 범위에서 질문과 관련된 범위를 선택하는 로직을 추가했다.
* 평가에서만 긴 근거의 중간을 삭제하던 3,000자 제한을 제거했다.
* 원 질문과 재작성 검색어를 함께 사용하는 기존 동작을 유지했다.

주요 구현 위치는 `back/app/services/rag.py`, `back/app/services/chat.py`, `back/scripts/ragas_eval.py`다.

작업 중단 후 최종 확인:

* 관련 pytest 14개 통과
* Ruff 통과
* 중간 검색 점검에서는 17개 질문 중 16개가 기대 조문 일부를 상위 5개에 포함했다.
* `rescue_train_protection`의 제321조는 당시 검색에서 누락됐다. 최신 어미 정규화 이후에는 재확인하지 못했다.

기존 전체 평가 결과는 다음과 같다. 이번 수정의 성능으로 보고하면 안 된다.

## 3. 남은 구현 순서

### ① 그래프 회귀와 검색 누락부터 해결

* **복원 조문과 기존 간선 연결:** 복원된 조문은 합성 ID를 사용하지만 KnowledgeEdge는 저장된 fragment ID를 참조한다. 원본 fragment와 복원 조문의 매핑을 유지해, 복원 조문에서 출발해도 승인 간선을 탐색하도록 한다. 이 문제는 코드 검토에서 확인한 위험이며 재현 테스트부터 작성한다.

* **복수 연결 범위 보존:** 현재 관련 범위를 여러 개 선택한 뒤, 단계별 링크 1개만 남기는 후속 처리에서 다시 버릴 수 있다. 같은 링크의 관련 범위는 하나의 근거로 묶고 원래 링크 ID·경로·위치를 유지한다.

* **제321조 검색:** 구원열차 요구·정거장 외 정차라는 조건으로 올바른 방호 조문이 우선되는지 확인한다. 케이스 이름이나 조문 번호를 하드코딩하지 않고 일반적인 검색 로직에서 해결한다.

* **근거 일치:** 정상 응답과 fallback 모두 생성기에 전달한 근거, API가 반환한 근거, 평가기가 받은 근거가 일치하도록 한다. 근거 번호와 인용 번호도 동일해야 한다.

### ② 재현 가능한 평가 실행기 완성

기존 평가 스크립트에 다음 기능을 추가한다.

* 선택 케이스 실행, 실행 ID별 결과 저장, 완료 케이스 재개
* 케이스 종료 시 즉시 출력·체크포인트 저장
* 질문, 답변 원문, 실제 전달한 전체 근거, reference, 문서 위치, 링크·hop·경로 저장
* 지표별 점수·오류와 라이브러리가 제공하는 판정 세부정보 저장
* 생성·평가 모델, 임베딩 모델, 평가 설정, 데이터셋 버전, 코드 식별 정보 저장
* 코드·설정·데이터셋이 달라지면 이전 결과를 이어 붙이지 않도록 재개 조건 검증

실패 케이스는 실패로 남기고 전체 평가를 미완료로 표시한다. 일부 성공한 케이스의 평균만으로 통과 처리하지 않는다.

기존 JSON 필드는 유지하고 다음 집계를 추가한다.

* 문서 전체 및 직접 검색·그래프 하위 그룹
* 일반 지식만의 집계
* 인사말 행동 검증
* 기존 방식의 비교 집계
* 목표 충족 여부와 평가 완료 여부

외부 채팅 API와 Flutter 인터페이스, DB 스키마 변경은 계획하지 않는다.

### ③ Reference V2를 원문에서 작성·고정

기존 reference에는 다음 문제가 있다.

* ATC 질문에 운전시각 기록인 제34조가 포함돼 있다.
* 비상제동 점검 질문에 제25조만 지정돼 있어 실제 점검 절차를 충분히 담지 못한다.
* 일부 그래프 질문은 PPT 절차를 묻지만 정답은 규정 조문만 포함한다.

각 질문에 필요한 사실과 조건을 원문 규정·PPT에서 확인해 V2 reference를 작성한다. 출처의 문서 버전, 페이지 또는 조문과 수정 사유를 함께 남긴다.

모델 답변이나 현재 검색 결과를 정답으로 복사하지 않는다. V2는 평가 전에 고정하고, 점수를 본 뒤 답변에 맞춰 수정하지 않는다. 원문 오류를 추가 발견하면 새 버전으로 기록한다.

기존 17개 문서 질문과 4개 일반 지식 질문은 유지한다. 기존 reference 결과와 V2 결과를 구분해 평가 기준 수정 효과와 제품 개선 효과를 혼동하지 않게 한다.

### ④ 실제 답변 품질을 반복 개선

* 근거 없는 보완 설명을 만들지 않는다.
* 관련성 점수를 올리기 위한 질문 복사나 평가용 문구 삽입은 하지 않는다.

실행 순서는 실패 케이스 평가 → 원인 수정 → 회귀 테스트 → 전체 평가다. 고정된 최종 코드·데이터셋·평가 설정에서 전체 평가를 2회 수행하고, 각 실행이 목표를 만족해야 완료로 판단한다. 두 결과를 모두 보존한다.

## 4. 테스트와 완료 판정

필수 회귀 시나리오:

* 여러 청크에 걸친 조문의 본문·예외·UTF-16 위치 보존
* 복원 조문에서 승인된 KnowledgeEdge로 1단계 탐색
* 미승인 링크 제외 및 2단계 링크 체인 보존
* 하나의 승인 링크가 가진 복수 관련 범위 보존
* 구원열차 방호 질문에서 제321조 검색
* 생성·응답·평가 근거와 인용 번호 일치
* 일반 지식에서 문서 검색 생략
* 인사말에서 자연스러운 인사 응답, general, 근거 0개
* 평가 중단·재개 시 중복 집계 방지 및 설정 변경 감지

작업 디렉터리를 `back`으로 두고 실행한다.

```bash
uv run ruff check app scripts tests
uv run pytest tests/test_chat.py tests/test_graph_rag.py tests/test_document_links.py
uv run --extra eval python -u -m scripts.ragas_eval
```

마지막 명령은 현재 전체 평가 진입점이다. 케이스 선택·재개 옵션은 아직 구현되지 않았다.

그래프 검증은 링크가 결과에 들어왔다는 사실과 실제 답변에 활용됐다는 사실을 분리한다. 승인 여부, 추가된 근거, 탐색 경로, 인용된 연결 근거를 각각 기록하며, 인용 여부만으로 의미적으로 올바른 활용을 단정하지 않는다.

완료 보고에는 두 번의 전체 평가 수치, 케이스별 미달 항목, 그래프 활용 결과, 인사말 검증, 변경 내용과 결과 파일을 포함한다. 목표 미달이면 달성했다고 보고하지 않고, 남은 원인과 다음 실험을 명시한다.

## 5. 다음 에이전트의 시작 지침

1. 현재 작업 트리와 보존된 결과를 읽는다. 저장소에는 다른 작업의 수정·미추적 파일이 많으므로 전체 초기화나 덮어쓰기를 하지 않는다.
2. 최신 코드는 테스트 14개와 Ruff가 통과했지만 전체 성능은 미검증임을 전제로 시작한다.
3. 구현 순서 ①의 합성 ID 그래프 회귀와 복수 범위 누락부터 재현·수정한다.
4. 평가 기록 기능과 Reference V2를 완성한 뒤 유료 전체 평가를 실행한다.
5. 기존 API 키를 사용하되 키·`.env` 본문을 출력하거나 결과 문서에 포함하지 않는다.

점수를 높이기 위해 지표 정의를 임의로 바꾸지 않는다.
