① 하이브리드 검색   임베딩 유사도 0.6 + BM25 0.4로 조문·슬라이드 단위 점수를 매긴다

② 1차 재정렬       상위 20개(RERANK_POOL)를 LLM이 보고 질문에 맞는 top_k개만 고른다 → 직접 근거 (hop 0)

③ 링크 확장        승인된 DocumentLink를 따라 연결된 규정·길라잡이 구간을 최대 2 hop까지 가져온다

## 3. 단계별 원리

### ① 하이브리드 검색 (`_Corpus.scores`)

- **검색 단위:** 원문 조각(Fragment)을 그대로 쓰지 않습니다. 규정은 `제n조` 단위로 묶고(`_article_units`), 길라잡이 슬라이드는 슬라이드 제목(예: "출입문 고장 – 점검사항")을 붙여 검색 단위를 만듭니다.
- **임베딩 유사도 (60%):** 질문과 단위의 코사인 유사도입니다. 뜻이 비슷한 표현을 찾습니다.
- **BM25 (40%):** 조사·어미를 떼어낸 한국어 토큰과 동의어 사전(`SEARCH_SYNONYMS`)으로 키워드 일치를 셉니다. 단어마다 기여도를 1로 제한하고 길이로 보정합니다. 그래서 긴 조문이 단어 수만으로 이기지 못합니다.
- **두 점수를 섞는 이유:** 임베딩은 "출입문 고장"과 "도어 불량" 같은 바꿔 말하기에 강합니다. BM25는 "제328조"나 차단기 이름 같은 정확한 용어에 강합니다.

### ② 1차 재정렬 (`_rerank`)

길라잡이 PPT는 같은 절차가 거의 같은 슬라이드 여러 장에 나뉘어 있습니다. 그래서 점수만 보면 실제 조치 단계가 담긴 슬라이드보다 도형만 있는 슬라이드가 위로 올라오기 쉽습니다.

이를 막기 위해 상위 20개 문단을 600자씩 잘라 LLM에 보여 주고, 질문의 모든 조건을 함께 다루는 문단만 고르게 합니다. 일반 규정, 용어 정의, 다른 고장, 목차와 표지는 고르지 않게 지시합니다. API 키가 없거나 호출이 실패하면 점수 순 상위 top_k로 대신합니다.

### ③ 링크 확장 (`_expand_links`)

`DocumentLink`는 관리자가 승인한 "이 길라잡이 페이지 ↔ 이 규정 구간" 연결입니다. 직접 근거가 링크의 한쪽 끝이면 반대쪽 구간을 hop 1 근거로 가져오고, 거기서 한 번 더 이어지면 hop 2가 됩니다.

- **문서 버전 처리:** 슬라이드는 문서 버전이 바뀌어도 같은 페이지·내용이면 링크를 따라갑니다(8d27362).
- **겹침이 없을 때:** 링크 대상 구간이 질문과 전혀 겹치지 않으면 가져오지 않습니다(`_relevant_target_selections`).
- **링크 데이터 정리:** 링크 데이터는 `back/scripts/clean_document_links.py`로 미리 정리했습니다. 관계없는 조문을 빼고, 끝에 딸려 붙은 제목을 잘라냈습니다.

### ④ 연결 근거 재정렬 — 이번 확정 변경 (2c2d5c6)

**이전 방식:**
- 직접 근거와 연결 근거를 `(직접 근거 우선, hop, 점수)` 순으로 한 줄로 세웠습니다.
- 그다음 `top_k × 3`개에서 잘랐습니다.
- 링크로 딸려 온 무관한 조문이 그대로 답변 모델에 들어가 Context Precision을 떨어뜨렸습니다.
- 반대로 정작 필요한 특칙(예: 5~8호선 특칙)은 잘려 나가기도 했습니다.

**지금 방식:**
1. 직접 근거(hop 0)는 ②에서 이미 고른 것이라 **모두 유지**합니다.
2. 연결 근거(hop ≥ 1)만 점수순으로 모아 `_rerank`에 다시 넣습니다. 이때 각 문단에 `(연결 근거)`와 `(자료: 문서명)` 표시를 붙입니다.
3. LLM에는 다음 규칙을 추가로 줍니다.
   - 연결 근거가 질문한 상황의 절차나 조치를 직접 다루면 반드시 고른다.
   - 직접 근거가 일반 절차만 다루면 특칙을 담은 연결 근거도 함께 고른다.
   - 질문과 직접 관련 없는 연결 근거는 뺀다.
4. 최대 `top_k × 2`개까지 고릅니다. 실패하거나 아무것도 고르지 않으면 연결 근거를 **넣지 않습니다**. 점수순 대체를 쓰지 않는 이유는, 연결 근거를 무조건 넣는 것이 Precision 하락의 원인이었기 때문입니다.

**효과:** 그래프 경유로 가져온 근거가 "링크가 있으니 넣는다"에서 "질문에 필요하니 넣는다"로 바뀌었습니다. 이것이 Context Precision 0.907의 주된 원인입니다.

### ⑤ 답변 생성

| 설정 | 값 | 이유 |
|---|---|---|
| `answer_reasoning_effort` | `medium` | 답하기 전에 근거 규칙을 점검할 여유가 생겨 누락과 엉뚱한 조문 인용이 줄었습니다. `low`일 때보다 Correctness가 높았습니다. |
| ChatService `top_k` | `5` | 3으로 줄이면 절차 일부가 빠져 Correctness가 떨어졌습니다. |
| `ANSWER_STYLE_RULES` | 제거 | "짧게, 질문한 것만" 지시는 절차 단계를 생략하게 만들어 Correctness를 깎았습니다. |

답변 모델에는 시스템 지시 두 가지를 줍니다. `GROUNDED_ANSWER_RULES`는 답변 전체의 규칙이고, `ANSWER_FOCUS_REMINDER`는 근거 바로 뒤에 붙는 자기 점검 질문입니다.

`GROUNDED_ANSWER_RULES`의 네 가지 규칙은 다음과 같습니다.

1. **범위:** 질문한 상황을 직접 규정한 조문(주 근거)으로만 답하고, 다른 조문의 조치를 덧붙이지 않습니다.
2. **원문 충실:** 주체, 조건, 순서, 시한, 수치, 스위치 명칭을 원문 그대로 씁니다.
3. **슬라이드:** 같은 고장 종류의 슬라이드만 쓰고, 도형 라벨을 이어 붙여 단계를 만들지 않습니다. 길라잡이 내용은 "길라잡이에 따르면"으로 구분합니다.
4. **형식:** 첫 문장을 결론으로 쓰고, 조문에 규정명을 붙이고, 내용마다 실제 근거 번호를 답니다.

ChatService는 여기에 메시지를 하나 더 넣습니다. 노선·상황 특칙이 근거에 있으면 그래프로 연결된 근거라도 반드시 포함하라는 지시입니다.

### ⑥ 인용 정리

- **`drop_invalid_citations`:** 존재하지 않는 `[근거 n]` 번호를 지웁니다.
- **`fix_citations`:** 각 문장과 근거의 글자 2-gram 겹침을 계산해, 실제로 내용을 담은 근거 번호로 바꿉니다.

## 4. 운영 판정 기준

`back/scripts/ragas_eval.py`의 `PILOT_CRITERIA`가 자동으로 확인하는 실사용 기준입니다.

| 항목 | 기준 |
|---|---|
| faithfulness 평균 / 최소 | ≥ 0.95 / ≥ 0.80 |
| context_recall 평균 / 최소 | ≥ 0.90 / ≥ 0.67 |
| context_precision 평균 | ≥ 0.85 |
| answer_correctness 평균 | ≥ 0.75 |
| 일반 지식 correctness 평균 | ≥ 0.90 |
| 범위 밖 질문 답변 거절률 | ≥ 0.90 |
| 응답 시간 p95 | ≤ 20초 |
| 인용 정확도 | ≥ 0.90 |

평가 공정성을 위해 다음은 하지 않습니다.
- 점수가 낮은 사례를 삭제하지 않습니다.
- 점수를 보정하거나 평가 프롬프트를 완화하지 않습니다.
- 정답을 검색기에 주입하지 않습니다.
- 잘 나온 결과만 골라 쓰지 않습니다.
- 특정 사례나 조문을 코드에 하드코딩하지 않습니다.
