# 챗봇 실사용 판정 기준

작성일: 2026-09-19
대상: `POST /api/chat`(사용자 채팅 앱)과 `POST /api/rag/query`

이 문서는 규정 챗봇을 현장에서 써도 되는지 판단하는 기준입니다. 운전·관제 절차는 틀리면 안전 문제로 이어지므로 기준을 **안전 → 검색 → 답변 품질 → 운영** 순으로 두고, 앞 단계가 미달이면 뒤 단계 점수와 관계없이 불합격으로 봅니다.

## 1. 사용 단계

| 단계 | 의미 | 조건 |
| --- | --- | --- |
| 개발 | 개발자·평가자만 사용 | 현재 상태 |
| 파일럿 | 지정된 소수 사용자가 **원문 확인을 전제로** 참고용으로 사용 | 2장의 모든 파일럿 기준 충족 |
| 정식 | 일반 사용자가 업무 참고 자료로 사용 | 2장의 모든 정식 기준 충족 |

정식 단계에서도 챗봇 답변은 규정 원문을 대신하지 않습니다. 화면에 "답변은 참고용이며 규정 원문을 확인하십시오" 안내와 근거 원문 링크를 항상 표시합니다.

## 2. 판정 기준

평가 수치는 `back/scripts/ragas_eval.py`의 Reference V2 기준입니다. "평균"은 문서 질문 전체 평균, "최저"는 사례별 최저값입니다.

### 2.1 안전 (차단 기준)

하나라도 미달이면 단계를 올리지 않습니다.

| 항목 | 측정 방법 | 파일럿 | 정식 |
| --- | --- | --- | --- |
| 근거 충실도 평균 | RAGAS Faithfulness | ≥ 0.95 | ≥ 0.97 |
| 근거 충실도 최저 | 사례별 Faithfulness | ≥ 0.80 | ≥ 0.90 |
| 치명 오류 | 현업 검토자가 답변 검토: 틀린 절차·수치·주체, 다른 상황의 조문 적용 | 0건 | 0건 |
| 인용 정확성 | 현업 검토: `[근거 n]`이 가리키는 원문에 그 내용이 실제로 있음 | ≥ 90% | ≥ 95% |
| 근거 없음 응답 | 문서에 없는 질문에 "근거를 찾지 못했다"고 답하고 추측하지 않음 | ≥ 90% | ≥ 95% |

충실도가 1.0 미만인 사례는 수치가 기준을 넘더라도 답변을 직접 읽고, 근거 없는 문장이 안전 절차에 관한 것이면 치명 오류로 셉니다.

### 2.2 검색

| 항목 | 측정 방법 | 파일럿 | 정식 |
| --- | --- | --- | --- |
| 근거 재현율 평균 | RAGAS Context Recall | ≥ 0.90 | ≥ 0.95 |
| 근거 재현율 최저 | 사례별 Context Recall | ≥ 0.67 | ≥ 0.80 |
| 근거 정밀도 평균 | RAGAS Context Precision | ≥ 0.85 | ≥ 0.90 |
| 그래프 활용 | 그래프 질문에서 승인 링크가 근거로 추가되고 답변에 쓰임(`graph_check.passed`) | 전부 통과 | 전부 통과 |

### 2.3 답변 품질

| 항목 | 측정 방법 | 파일럿 | 정식 |
| --- | --- | --- | --- |
| 정답 일치도 평균 | RAGAS Answer Correctness | ≥ 0.75 | ≥ 0.85 |
| 핵심 요소 누락 | 현업 검토: 정답의 필수 조치·조건이 빠진 답변 비율 | ≤ 10% | ≤ 5% |
| 질문 관련성 | RAGAS Answer Relevancy ÷ 같은 질문의 **정답 문장 보정값** | ≥ 0.95 | ≥ 0.95 |
| 일반 지식 정확성 | 일반 질문 4개 Answer Correctness 평균 | ≥ 0.90 | ≥ 0.90 |
| 인사말 | 근거 없이 `general`로 자연스럽게 응답 | 통과 | 통과 |

**관련성을 절대값이 아니라 보정값 대비 비율로 보는 이유:** 이 지표는 답변에서 질문을 거꾸로 만들어 원래 질문과 임베딩 유사도를 잽니다. 현재 설정에서는 V2 정답 문장을 그대로 넣어도 평균 0.811이라, 절대값 0.9는 질문 문구를 답변에 복사하지 않고는 도달할 수 없습니다. 보정값은 평가 설정(평가 모델, 임베딩 모델, 프롬프트)이 바뀔 때마다 다시 측정합니다.

**정답 일치도를 0.9로 두지 않는 이유:** 이 지표는 정답에 없는 사실을 오답처럼 감점합니다. 같은 조문에 있는 맞는 내용이라도 정답이 생략했으면 점수가 깎이므로, 수치만으로 판단하지 않고 현업 검토의 핵심 요소 누락 항목과 함께 봅니다.

### 2.4 평가 자체의 신뢰성

| 항목 | 파일럿 | 정식 |
| --- | --- | --- |
| 평가 질문 수 | 현재 17 + 일반 4 + 문서에 없는 질문 10 | 문서 질문 50개 이상 + 문서에 없는 질문 20개 이상 |
| 질문 구성 | 현재 구성 | 조문 단일, 여러 조문, 가이드+규정, 후속 질문(대화 이력), 애매한 질문을 각각 5개 이상 |
| 정답 작성 | V2 고정 | 원문에서 작성하고 현업 담당자가 검토한 뒤 평가 전에 고정 |
| 반복 평가 | 같은 코드·설정으로 전체 평가 2회, 두 번 모두 기준 충족 | 동일 |

`docs/ragas-improvement-handoff.md`의 금지 사항을 그대로 적용합니다. 낮은 사례 삭제, 점수 보정, 평가 프롬프트 완화, 정답의 검색기 주입, 잘 나온 결과만 골라 쓰는 재시도, 관련성용 질문 복사는 하지 않습니다.

### 2.5 운영

| 항목 | 파일럿 | 정식 |
| --- | --- | --- |
| 응답 시간 | 문서 질문 p95 ≤ 20초 | p95 ≤ 10초 |
| 외부 API 장애 | OpenAI 오류 시 오류를 숨기지 않고 근거 발췌 또는 안내 문구로 응답 | 동일, 장애 알림 포함 |
| 설정 | `DATABASE_URL`, `STORAGE_ROOT`, `LOCAL_DOCUMENT_ROOTS`가 실제 경로를 가리킴 | 동일 |
| 원문 확인 안내 | 채팅 화면에 안내 문구와 근거 링크 표시 | 동일 |
| 변경 관리 | 코드·프롬프트·문서 인덱스가 바뀌면 2.1~2.3 재평가 | 동일 |

**판정: 개발 단계 유지.** J는 자동 측정 항목을 모두 충족했지만 K는 guide_psd 재현율 0.50으로 미달이라 "같은 코드로 2회 모두 충족"을 채우지 못했습니다. K의 guide_psd 근거는 J(0.78)와 같은 슬라이드 28·제46·241·242조에 제46조가 하나 더 붙은 것이어서 검색 저하가 아니라 평가 모델 판정 편차입니다. 같은 현상으로 staff_h는 flooding 충실도 0.667을 받았는데, 같은 답변·근거를 다시 5회 채점하면 1.0, 1.0, 1.0, 1.0, 0.667이었습니다(평가 모델 temperature 1). 금지 사항에 따라 이 결과를 제외하거나 재시도로 대체하지 않았습니다.

### 2차 개선 내용 (원문 대조로 찾은 오류 기준)

| 발견한 문제 | 조치 |
| --- | --- |
| 모델이 인용 번호를 처음 쓴 순서대로 다시 매김(제321조를 [근거 1]로 인용) | 답변 후 문장과 근거 원문을 글자 2-gram으로 대조해 단일 인용 번호를 바로잡는 `fix_citations` |
| ATC 속도 질문에 TC 동시 고장·ADU 고장 슬라이드 인용 | 슬라이드마다 고장 종류 제목을 뽑아 위치에 표시(`슬라이드 37 · 전부 TC1… 고장 시`), 다른 고장 슬라이드 인용 금지 규칙 |
| 링크 근거 라벨이 첫 조문만 표시(`제66조`인데 제67·144조 포함) | 근거 안의 모든 조문 표시(`제66조·제67조·제144조`) |
| 재작성 검색어가 길어지면 링크 범위 중 제67조(45㎞/h)가 잘림 | 링크 범위 선택을 "최고 점수−1"에서 "최고 점수의 절반 이상, 최대 4개"로 변경 |
| PSD 도형 라벨을 이어 붙여 틀린 순서 생성 | 동사가 있는 문장만 조치로 쓰고 도형 라벨은 단계로 만들지 않는 규칙 |
| 원문에 없는 주체("기관사는")·수식어("즉시") 추가, 제330조 호 번호 재부여, 인접선로 ①항(후속열차 방호 전) 누락 | 답변 규칙을 우선순위 목록으로 재작성하고 답변 단계만 추론(`ANSWER_REASONING_EFFORT=medium`) 사용 |
| 편의점 입점 계약 질문에 안전관리 계약 절차로 답함 | 다른 대상·업무의 근거는 답이 아니라는 규칙 |
| 채팅 화면에 참고용 안내 없음 | 사용자 앱 근거 목록 위에 "답변은 참고용, 원문 확인" 안내 |

추론 사용으로 답변은 매번 조금씩 달라질 수 있습니다(temperature 0 불가). 응답 시간 p95는 16~18초로 파일럿 기준(20초) 안이지만 정식 기준(10초)에는 못 미칩니다.

### 다음 단계

1. 현업 검토자가 `back/runtime/staff_review_20260919_final_j.md`(또는 `_k.md`)로 치명 오류·인용 정확성·핵심 요소 누락을 표시합니다. 자동 인용 검사에서 걸린 문장은 ⚠로 표시돼 있습니다(대부분 "정거장외에서", "제1항의 보고를 받은" 같은 한정어 생략).
2. 평가 판정 편차 처리 방식(예: 사례별 지표를 평가 모델로 3회 채점해 중앙값 사용)을 기준 개정으로 정할지 결정합니다. 기준을 바꾸면 이전 결과와 구분해 기록합니다.
3. guide_psd V2 정답의 "운전관제에 보고" 문장이 근거 자료 어디에 있는지 현업에 확인합니다. 원문에 없으면 V3로 기록합니다.

## 4. 판정 절차

1. 코드·프롬프트·평가 세트를 고정하고 커밋 해시를 기록합니다.
2. `back/`에서 전체 평가를 2회 실행합니다.
   ```powershell
   uv run --extra eval python -u -m scripts.ragas_eval --reference-version v2 --run-id <날짜>_a
   uv run --extra eval python -u -m scripts.ragas_eval --reference-version v2 --run-id <날짜>_b
   ```
3. 평가 설정이 바뀌었으면 관련성 보정값을 다시 측정합니다.
4. 현업 검토자가 두 실행 중 하나의 답변 전체를 검토해 치명 오류, 인용 정확성, 핵심 요소 누락을 기록합니다.
5. 2장 표를 채워 이 문서 3장을 갱신하고, 결과 파일 경로와 검토 기록을 함께 남깁니다.
